# Timeline Seesaw — Web Demo

`gdd/` 폴더의 기획 문서를 기반으로 만든 빌드 도구 없는 순수 HTML/CSS/JS
프로토타입입니다. 무림 4문파(적·흑·백·자)와 스테이지 1~10 런 전체가
플레이 가능합니다. 용어는 [gdd/12](../gdd/12-murim-terms.md)를 따릅니다 —
기세 · 틈 · 아/적 · 합 · 파훼.

## 실행 방법

Node.js 없이도 바로 열 수 있습니다.

```bash
open index.html
```

드래그 앤 드롭(HTML5 Drag and Drop API)이 `file://`에서 정상 동작하지
않는 브라우저도 있으니, 문제가 있으면 로컬 서버로 열어주세요.

```bash
python3 -m http.server 8000
```

이후 브라우저에서 `http://localhost:8000` 접속.

## 구현 범위

**스테이지 1~10 런 전체**가 플레이 가능합니다 — 4색 덱 선택 →
**신병이기 선택** → 비무 → 전리품(초식 1장) → **갈림길(3지선다)** → 걸음 →
다음 비무. 걸음은 수련장 · 주루 · 문파 방문 · **고묘** · 비무대회 · 기연
여섯이고, 무기(한 합의 규칙)와 유물(강호행의 규칙)이 두 축으로 얹힙니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `data.js` | 4색 덱·보상 풀·강화표·적 10종·상수 |
| `engine.js` | 전투 엔진 (게이지, 카드 효과, 적 기술 루프) |
| `run.js` | 런 진행 (비무, 전리품, 갈림길과 걸음, 회복) |
| `ui.js` | 화면 라우팅·렌더링·연출 |
| `sim.js` | 밸런스 시뮬레이션 하네스 (게임에서 로드하지 않는 개발용) |
| `guide.html` | 처음 여는 사람을 위한 안내 한 장 (gdd/16) |

> **`index.html`에 스크립트를 새로 추가하지 마세요.** 카드 설명 생성기를
> `text.js`로 분리했다가, `index.html`이 캐시된 브라우저에서 그 파일만 안
> 불려와 화면이 통째로 죽는 사고가 났습니다(`TS_Text is not defined`).
> 지금은 `ui.js` 안에 있습니다. `guide.html`은 새 페이지라 이 문제가
> 없습니다 — 대신 `data.js`와 `ui.js`만 읽고 `init()`은 부르지 않습니다.

### 설명 문구는 한 곳에만 씁니다

규칙은 `data.js`의 **`RULES`**, 용어는 **`GLOSSARY`** 하나입니다. 전투
화면의 규칙 창, `guide.html`의 규칙 절, 용어 툴팁, 용어표가 전부 같은
배열을 읽습니다. 숫자는 위쪽 상수에서 끌어오므로 `DRAW_ACTION_COST`를
바꾸면 설명도 따라 바뀝니다.

**안내 페이지의 화면 예시는 스크린샷이 아닙니다.** 같은 `style.css`를 쓰고,
기세 축은 `TS_UI.buildGaugeCells`, 카드 설명은 `TS_UI.describe`로 그립니다.
스크린샷이면 수치를 조정한 날 조용히 낡습니다 — 이 프로젝트가 강화표에서
이미 세 번 겪은 종류의 오류입니다.

### 밸런스 시뮬레이션 돌리는 법

브라우저 콘솔에서:

```javascript
fetch('sim.js').then(r => r.text()).then(eval);
['RED','BLUE','BLACK','YELLOW'].map(c => TS_Sim.run(c, 150));
TS_Sim.run('RED', 60, { search: true });   // 최적에 가까운 플레이
TS_Sim.run('RED', 120, { casual: true });  // 무지성 플레이 (하한)
TS_Sim.lint();                             // 데이터 점검 (아래 참고)

// 무기를 고정해 한 자루씩 재기 (null = 맨손, 'random' = 무작위)
TS_Sim.run('RED', 90, { casual: true, weapon: 'spear' });
TS_Sim.run('RED', 90, { casual: true, relic: 'mirror' });
TS_DATA.WEAPONS_ENABLED = false;           // 무기 축을 통째로 끄고 비교

// 갈림길이 밸런스에 얼마를 보태는지 가르는 A/B
TS_DATA.CROSSROAD_ENABLED = false; TS_DATA.STAGE_HEAL_RATIO = 0.5;
```

간단한 탐욕 AI로 런을 자동 플레이해 클리어율·평균 도달 스테이지·턴당
카드 사용 수·사망 스테이지 분포를 돌려줍니다. **턴당 카드 사용 수는 무한
루프 탐지기로도 쓰입니다** — 정상값은 2.5~3.8이고, 한 자리를 크게 넘으면
메모리나 손패를 순증시키는 카드 조합이 생겼다는 뜻입니다.

## 밸런스 현황 (백 구조 수정 후)

**클리어율은 버그가 아니라 난이도 표기입니다.** 모든 문파가 같은 승률일
필요는 없고, 낮은 쪽이 "생각을 많이 하고 써야 하는 문파"면 됩니다.

| 문파 | 초심자(도달) | 탐욕 | 탐색 | 파훼율 |
| --- | --- | --- | --- | --- |
| 적(화산) | 4.2 | 40% | 85% | 15% |
| 흑(무당) | 4.2 | 24% | 69% | 21% |
| 백(금강사) | 4.0 | 15% | 79% | 16% |
| 자(마교) | 4.2 | 8% | 71% | 10% |

초심자 도달이 4.0~4.2로 모입니다. 네 색이 이만큼 붙은 적은 없었습니다.

### 백은 이길 방법이 하나뿐이었다

백은 오래 가장 망가진 색이었고, 원인은 수치가 아니라 구조였습니다.
필드를 하나씩 지워 보면 바로 드러납니다.

| 백에서 지운 것 | 탐욕 | 탐색 |
| --- | --- | --- |
| 아무것도 (기준) | 96% | 98% |
| `surge` | 94% | 100% |
| **`breakThresholdDown`** | **2%** | 25% |

**한 필드가 컬러 하나를 켜고 껐습니다.** 이유는 둘입니다.

1. **빈틈 축소가 전투 내내 남았습니다.** 파훼는 계단 함수라(넘거나 못
   넘거나) 임계점을 영구히 내리면 "매 합 파훼" 아니면 "무의미" 둘 중
   하나가 됩니다. → **이번 합에만 남도록** 바꿨습니다
   ([gdd/2-3](../gdd/02-boss-intent-thresholds.md)).
2. **백은 파훼 말고 이길 방법이 없었습니다.** 합당 피해가 4.7로 흑(9.8)의
   절반이라, 3스테이지 철벽 무승(체력 114 · 빈틈 9 · 운기마다 방어도 +10)
   에서 초심자 60런 중 45런이 죽었습니다. → **반탄을 두 번째 승리 수단으로**
   만들었습니다 ([gdd/3-5](../gdd/03-color-archetypes.md)).

반탄은 피격 1회로 소모되던 시절엔 함정 카드였습니다 — 통째로 지워도
클리어율이 98% → 93%로만 움직였습니다. 적 페이즈 하나를 버티게 하니
"적이 때리는 횟수 = 내 화력"이 되어, 파훼(몰아치기)와 자원이 겹치지
않는 진짜 두 번째 라인이 됐습니다.

고친 뒤 한 라인씩 막아 봐도 색이 죽지 않습니다.

| | 탐색 | 초심자 도달 |
| --- | --- | --- |
| 두 라인 다 | 83% | 4.1 |
| 파훼 라인 봉쇄 | 71% | 3.5 |
| 반탄 라인 봉쇄 | 88% | 3.2 |

### 통하지 않은 손잡이 (기록)

같은 문제에 대고 먼저 시도했다가 **효과가 없던** 것들입니다. 다시 시도할
이유가 없다는 기록으로 남깁니다.

| 시도 | 결과 |
| --- | --- |
| 빈틈 축소 하한을 `-4` → `-2`로 | 파훼율 39% → 38%. 무의미 |
| 방어도를 합 사이에 50% 이월 | 초심자 3.4 → 3.3 (하한 그대로), 탐색 84 → 87 (상한만 올림) |
| 반탄 수치 절반 | 탐색 84% → 98%. AI가 파훼 라인으로 되돌아갈 뿐 |
| 금강불괴에 반탄 2 부여 | 초심자 3.1 → 3.5, **탐색 81 → 97**. 상한만 폭발 |
| 시작 덱에 강기충 추가 | 아무 변화 없음 (초심자가 방어도 없이 지름) |
| **금강저 피해 11 → 14** | **초심자 3.1 → 4.0, 탐색 81 → 79.** 하한만 올린 유일한 손잡이 |

### ⚠️ 점수 함수는 조용히 틀린다

`sim.js`의 `score()`에 필드가 빠지면 그 카드는 0점이 되고, 0점은
**"버려도 되는 카드"**라는 뜻입니다. 실제로 두 번 당했습니다.

1. B라인 필드(`surge`·`sealSkill`·`drainPower`)가 통째로 누락 → AI가
   문파 방문 교환에서 백의 `파계진언`을 매번 내다 버림
2. `breakThresholdDown`을 고정 5로 계산 → 가중치를 3 → 5로 올린 것만으로
   백 클리어율이 24% → 98%

**새 카드 필드를 추가하면 반드시 `score()`에도 넣으세요.** 이제
`TS_Sim.lint()`가 모르는 필드를 잡아 줍니다.

### 무기는 승률이 아니라 발동률로 잰다

승률은 40런에서도 ±10포인트씩 흔들려 무기 비교에 못 씁니다. **규칙이 합당
몇 번 발동하는가**가 훨씬 안정적입니다. 창(槍)이 그 예입니다.

| 창의 조건 | 합당 발동 |
| --- | --- |
| 같은 초식을 **연달아** | 0.02회 (탐색 정책조차) |
| 같은 초식을 **한 합 안에** | 0.20회 |
| **틈 3 이상**의 초식 (현재) | 0.44회 |

지금 다섯의 발동률은 검 0.36 · 곤 0.41 · 창 0.44 · 도 0.86이고, 자주
터지는 무기일수록 한 방이 작습니다(도 +5 vs 창 +12). 자세한 내용은
[gdd/14-6](../gdd/14-weapons.md).

### ⚠️ 하네스가 못 재는 것이 있다

유물 다섯 중 셋은 **AI가 구조적으로 쓰지 못합니다.**

| 유물 | 초심자 도달 (없음 4.28) | 왜 |
| --- | --- | --- |
| 호심경 · 오도비 | 5.17 | 잰다 |
| 각인석 | 4.45 | **정책을 가르친 뒤에야** (탐욕 26% → 32%) |
| 이문록 | 4.27 (±0) | **못 잼** — 정보를 읽는 정책이 없다 |
| 축지부 | 4.20 (−0.08) | **못 잼** — 선택의 질을 못 따진다 |

이문록과 축지부는 정보와 선택의 질을 주는 물건이라, 무작위로 고르는
AI에게는 값이 0입니다. **수치가 낮다고 약한 게 아니라 하네스가 볼 수 없는
종류이므로, 수치만 보고 상향하면 안 됩니다.**

각인석은 "제시된 카드가 덱 중간값보다 못하면 거절한다"는 규칙을 정책에
넣자마자 측정 가능해졌습니다. 나머지 둘도 그런 규칙을 찾으면 잴 수
있습니다.

### 만들어 놓고 안 보이면 없는 것과 같다

유물을 기연과 비무대회로만 냈더니 **런의 77%가 유물을 한 번도 못 봤습니다.**
게다가 탐욕 정책은 기연을 **런당 0.00회** 골랐습니다 — 기연 점수(38)가 늘
곁에 있는 수련장(45+)에 밀려, 기연 4종이 통계에서도 통째로 빠져 있었습니다.

고묘(古墓) 걸음을 넣고 기연 점수를 손본 뒤:

| | 유물 0개로 끝난 런 | 런당 기연 |
| --- | --- | --- |
| 고묘 없음 | 77% | 0.00회 |
| 고묘 있음 | **18%** | 0.62회 |

### 데이터 점검 — `TS_Sim.lint()`

```javascript
TS_Sim.lint();   // ['이상 없음'] 이어야 정상
```

세 가지를 봅니다. 전부 **화면에 아무 경고도 안 남기고 조용히 틀리는**
종류입니다.

1. **강화가 카드를 약하게 만드는가** — 실제로 흑의 `연환장`(피해 12 →
   강화하면 9)과 `행운유수`(5 → 4)가 걸렸습니다. 기본 수치를 올릴 때
   강화표를 같이 안 고쳐서 생긴 것으로, 강화할수록 나빠지고 있었습니다.
2. **되감기 무한 루프** — `cost - rewind >= 1` 불변 규칙
3. **`score()`가 모르는 필드**

### (이전 기록) 실력에 따른 격차 — 아래 수치는 점수 함수를 고치기 전 값

**초심자 2~79% vs 탐색 90~99%.** 같은 게임인데 실력에 따라 결과가 완전히
갈립니다. 그리고 이 격차는 난이도 수치로 못 좁힙니다 — 실측입니다.

| 적 피해 배율 | 탐색 | 초심자(화산파 도달) |
| --- | --- | --- |
| ×1.00 (현행) | 90~99% | 6.8 |
| ×1.15 | 95~98% | — |
| ×1.22 | 85~93% | — |
| ×1.26 | 57~81% | **4.9** |
| ×1.30 | 57~81% | 4.8 |

적 피해를 26% 올리면 탐색은 57~81%로 적당해지지만 **초심자는 4~5스테이지에서
전멸**합니다. 반대로 지금 수치는 초심자에게 적당하고(도달 6.8 — 실제 플레이
체감과 일치) 최적 플레이에는 너무 쉽습니다.

**즉 난이도 손잡이로는 둘 중 하나만 만족시킬 수 있습니다.**

### 파훼 보상 축소는 답이 아니었습니다 (검증 완료)

"최적 플레이가 파훼를 노려서 강한 것"이라는 가설을 세우고 파훼 보상을
요소별로 껐다 켜 봤습니다. **틀렸습니다.**

| 파훼 구성 | 탐색 | 초심자 |
| --- | --- | --- |
| 현행 (취소 + 기절 + 사혈 노출) | 93/85/95/100 | 2/0/67/17 |
| 기절 제거 | 88/80/100/97 | — |
| 예산 절반 + 기절·사혈 제거 | 82/**30**/**58**/97 | **0/0/0/3** |

- **기절(다음 페이즈까지 취소)을 통째로 없애도 수치가 안 움직입니다.**
- 파훼율 자체가 탐색 15~22% / 초심자 5~30%로 **탐색 정책이 파훼를 더 쓰지도
  않습니다.** 백은 오히려 초심자가 더 많이 냅니다(30% vs 22%).
- 가장 강한 축소안은 문파별로 제각각 움직이고(자는 97%로 거의 그대로)
  **초심자를 먼저 전멸시킵니다.**

즉 실력 격차는 **한 메커니즘의 문제가 아니라 "잘 두는 것 자체의 값"**입니다.
파훼·되감기·패 파기를 깎아도 격차는 안 좁혀지고 바닥만 내려갑니다.

### 그래서 남는 답: 난이도 단계

이 격차는 고칠 버그가 아니라 **난이도 단계로 푸는 문제**입니다 —
로그라이크가 승천(Ascension)·열기(Heat)로 푸는 바로 그 문제입니다.
아래 실측이 그대로 단계 설계의 근거가 됩니다.

| 적 피해 배율 | 탐색 | 초심자 (화산파 도달) |
| --- | --- | --- |
| ×1.00 | 90~99% | 6.8 |
| ×1.22 | 85~93% | — |
| ×1.26 | 57~81% | 4.9 |

`BREAK_STUNS_NEXT_PHASE` · `BREAK_GRANTS_VULNERABLE` · `BREAK_BUDGET_RATIO`
는 이 검증을 위해 만든 손잡이라 그대로 남겨 뒀습니다 (기본값 = 현행 동작).

### (이전 기록) 백은 초심자가 탐욕보다 3배 잘합니다 (74% vs 24%)

> ⚠️ 이 절의 수치는 점수 함수를 고치기 전 값이라 신뢰할 수 없습니다.
> 당시 AI는 백의 `파계진언`을 내다 버리고 있었습니다. 현재 수치는 위
> "밸런스 현황"을 보세요.

**"기세를 아껴 쓰기"와 "파훼 노리기"가 서로 반대 방향이라서** 생긴 일입니다.

| 백 · 정책 | 파훼율 | 합당 피격 |
| --- | --- | --- |
| 탐욕 (딱 맞춰 아껴 씀) | 10% | 3.0 |
| 초심자 (그냥 지름) | **31%** | **1.6** |

초심자는 낼 수 있는 카드를 안 따지고 제일 센 걸 질러서 몰아치기가 빨리
쌓이고, 파훼가 세 배 자주 납니다. 파훼는 적 페이즈를 통째로 지우므로
피격이 절반이 됩니다. 반대로 탐욕 정책은 기세를 알뜰하게 쓰느라 몰아치기가
안 쌓여 파훼를 거의 못 냅니다.

**둘 중 어느 쪽이 문제인지는 아직 미정입니다.**
- 게임 쪽 문제라면: 파훼 보상(적 페이즈 전체 취소)이 너무 커서 "알뜰함"이
  함정이 된 것입니다.
- AI 쪽 문제라면: 탐욕 정책이 파훼를 **합 단위로 계획**하지 못하는 것뿐입니다.
  (합마다 "파훼가 닿으면 큰 카드 우선"으로 고쳐 봤더니 조건이 거의 항상
  참이라 큰 카드를 낭비해 오히려 나빠졌습니다 — 되돌렸습니다.)

**아래 밸런스 수치는 탐욕 정책 기준이라 이 편향을 안고 있습니다.**

### 스테이지별 곡선 (4문파 × 45런)

| # | 사망률 | 클리어 시 HP | 파훼율 | 평균 합 |
| --- | --- | --- | --- | --- |
| 1 | 0% | 84% | 18% | 4.5 |
| 2 | 0% | 81% | 32% | 4.5 |
| 3 | 1% | 47% | 0% | 5.9 |
| 4 | 0% | 51% | 2% | 5.7 |
| 5 | 1% | 56% | 15% | 5.0 |
| 6 | 1% | 55% | 13% | 4.9 |
| 7 | 3% | 40% | 1% | 6.9 |
| 8 | 8% | 59% | 29% | 6.4 |
| 9 | **27%** | 44% | 10% | 5.6 |
| 10 | **29%** | 36% | 3% | 6.4 |

사망률이 0 → 29%로 단조 상승하고 클라이맥스가 9·10에 있습니다. 클리어 시
체력도 84% → 36%로 내려가 **체력이 실제 자원으로 기능합니다.**

**파훼율이 스테이지마다 다른 것이 의도입니다** — 빈틈이 작은 적(2·8번)은
파훼가 주력 전술이고, 큰 적(3·7번)은 정면 승부를 강요합니다.

> 클리어율은 런당 편차가 커서 50~100런으로는 ±20%p까지 흔들립니다.
> 문파를 비교할 때는 200런 이상을 쓰세요.

### "어려운 문파"와 "약한 문파"를 가르는 법

승률만으로는 둘을 구분할 수 없습니다. 그래서 하네스에 **계획형 정책**을
넣었습니다 — 패 파기는 손패가 4장 이상일 때, 연계는 2장 깐 뒤, 흘리기는
겹쳐 쓰지 않는 정도의 사람이 할 법한 판단만 추가한 것입니다.

```javascript
TS_Sim.run('RED', 200, { planned: true })
```

**두 정책의 차이가 곧 그 문파의 "생각할 여지"입니다.** 적(赤)은 +11%p로
순서를 짜면 실제로 보상받는 반면, 나머지는 거의 움직이지 않습니다. 승률이
낮은 문파를 조정할 때 이 값을 먼저 보세요 — **상승폭이 크면 어려운 것이고,
0에 가까우면 그냥 약한 것**이라 조치가 정반대입니다.

이 문서 초기 측정에서는 백 외 세 문파가 클리어율 0%, 평균 도달 6.4~7.3이었습니다.
**네 문파 모두 최종 스테이지권까지 도달**하게 됐지만 클리어율 격차는 남아
있습니다.

### 무엇이 격차를 만들었나

시뮬레이션으로 확인한 순서대로입니다.

1. **화력은 병목이 아니었다.** 고티어 피해를 올려도 백만 올라갔고, 적
   피해를 15% 낮추자 오히려 격차가 벌어졌습니다. 사망 시점의 보스 잔여
   체력은 어느 문파나 15~22%로 비슷했습니다 — 아슬아슬하게 지는 것이지
   화력이 모자란 게 아니었습니다.
2. **문제는 "쌓인 자원을 쓸 출구"의 유무였다.** 문파마다 출구를 하나씩
   주자(적 `chain`/`chainBlock`, 흑 `discardAll`, 백 `blockToDamage`,
   자 `lifesteal`) 해당 문파가 즉시 올라왔습니다. 자(紫)는 `생명 착취`에
   흡혈을 붙인 것만으로 5.8 → 7.5가 됐습니다.
3. **적(赤)은 틈 구조 자체가 문제였다.** 합의 절반을 `적5`로 마감해
   적에게 만점 예산을 넘기고 있었고(합당 피격 4.9 vs 백 0.9), 원인은
   틈 5짜리 피니셔였습니다. 같은 화력을 중간 틈의 연계로 옮기자
   8.1 → 8.8로 올랐습니다.
4. **티어 스케줄이 한 칸 어긋나 있었다.** 스테이지 8을 티어3 카드 없이
   맞고 있어 사망의 절반 이상이 그 한 스테이지에 몰렸습니다. 티어가 열리는
   시점을 한 칸 앞당기자 적·자가 각각 +0.5, +0.7 올랐습니다.
5. **적에게 개성이 없으면 스테이지가 늘어나도 같은 싸움입니다.** 빈틈과
   클로저 성격(패도/노회)을 적 스탯으로 만들자, 같은 엔진에서 네 종류의
   다른 문제가 나왔습니다. 특히 **노회형은 얕게 넘겨도 최소 보장(`아3`)만
   돌려주므로** 버퍼를 쌓는 플레이 자체를 막습니다 — 난이도가 아니라
   전술을 바꾸는 스탯입니다.
6. **빈틈이 작은 적에게는 낮은 HP를 짝지어야 합니다.** 자주 파훼당하는
   적이 HP까지 높으면 소모전이 되어, 버프가 누적되는 쪽에 일방적으로
   유리해집니다. 실제로 그 조합을 줬더니 그 한 스테이지에서 자동 플레이의
   30%가 죽었습니다.
7. **경감 수단은 출구와 별개 축입니다.** 흑(黑)은 화력이 4문파 중 1위(합당 35.7)
   인데도 최하위였는데, 원인은 **합당 방어도 0.1**이었습니다(백은 5.1).
   흘리기(`evade`)를 주자 곧바로 29% → 41%로 올랐습니다.
8. **파훼가 죽어 있었습니다 — 규칙이 서사와 반대로 작동했습니다.**
   파훼율이 0~1%(흑은 0.0%)였고, 가장 잘 무너져야 할 적조차 0.0%였습니다.
   원인은 구조입니다. 합은 기세가 `0`을 넘는 순간 끝나므로 파훼는 늘
   "마지막 한 장의 단독 점프"여야 했고, 필요한 틈은 `빈틈 + 지금 버퍼`
   였습니다 — **버퍼가 깊을수록 파훼가 더 불가능해졌습니다.** "버퍼를 쌓아
   파훼를 노린다"는 원래 서사와 정반대입니다. 판정을 **한 합에 지불한 틈의
   합계**로 바꾸자 0~1% → 6~11%가 됐고, 깊은 버퍼가 처음으로 파훼로
   이어졌습니다 ([gdd/02 2-1](../gdd/02-boss-intent-thresholds.md)).
   부수 효과로 **파훼가 흑(무당)의 전술**이 됐습니다 — 되감기로 합을 늘려
   몰아치기를 쌓는 문파라 파훼율이 10.9%로 압도적입니다.
9. **드로우 초식이 손패를 영구히 불렸습니다.** 보충량에서 연환 드로우는
   빼는데 **드로우 초식으로 뽑은 장수는 안 빼고 있어서**, 드로우 초식 한
   장당 손패가 합마다 +1씩 쌓였습니다. 흑(무당)의 합 시작 손패가 8.5장까지
   갔습니다. 차감을 넣자 6.3장으로 안정됐지만 흑의 클리어율이 63% → 16%로
   떨어졌습니다 — **흑이 그 누수 위에 서 있었다는 뜻**이라, 패 파기 계수를
   1.5배로 올려 보상했습니다.
   손패 크기에 뚜껑을 씌우는 안도 재봤는데, **손패가 안 불어나던 문파까지
   함께 끌어내려**(백 58% → 39%) 정밀도가 떨어졌습니다. 차감이 정확한
   수단입니다 ([gdd/07 7-2](../gdd/07-turn-economy-revision.md)).
10. **한 문파에게만 시소 규칙이 꺼져 있었습니다.** 백은 어느 수치를 깎아도
   93%에서 안 움직였습니다 — 방어도 −30%도, 반탄 제거도, 임계점 조작
   제거도. 착지별로 재 보니 답이 나왔습니다: **합의 75%를 `적2`에 착지시키고
   거기서 평균 0.8 피해만 받고 있었습니다**(적은 `적3`에서 6.6). 마무리
   일격이 방어도에 통째로 먹혀 "작게 넘기면 큰 게 온다"가 백에게만 무효였던
   것입니다. **클로저 관통**([gdd/08 8-4-2](../gdd/08-boss-skill-loop.md))을
   넣자 93% → 42%가 됐고, 그 뒤로는 방어도 수치를 되돌려도 거의 안 움직입니다.
   백의 축은 방어도에서 **반탄**으로 옮겨갔습니다 — 지금 반탄을 지우면
   42% → 17%입니다.

### 남은 과제

- **흑이 67%로 크게 올랐습니다.** 파훼 규칙 변경의 최대 수혜자입니다 —
  되감기가 "합을 늘리는 유틸"에서 "파훼로 가는 경로"가 됐기 때문입니다.
  이제 흑은 약한 문파가 아니지만, 계획 상승폭이 여전히 낮아(−5%p) 잘
  써서 이기는 게 아니라 자동으로 이기는 쪽에 가깝습니다.
- **백/자의 파훼율이 1%대**입니다. 초식이 적게·무겁게 나가서 몰아치기가
  안 쌓입니다. 두 문파가 파훼를 안 써도 각자 이길 길(방어도·반탄 / 흡혈)이
  있으니 문제는 아니지만, 백의 빈틈 조작 카드는 정작 백이 못 쓰는 상태라
  **다른 문파에게 더 어울리는 효과**일 수 있습니다.
- **자 76%**가 가장 쉬운 문파입니다. 흡혈은 클로저 관통에도, 파훼 규칙
  변경에도 영향을 받지 않아 두 번의 큰 변경에서 모두 안 깎였습니다.
- 자동 AI는 방어·회복을 피해와 1:1로만 평가합니다. 실제 플레이어는 상황에
  맞게 쓸 수 있으니 위 수치는 하한선으로 보는 편이 맞습니다.

| 흡혈 기준 피해 | 방어도 흡수 전 피해 기준 | 카드 설명("입힌 피해의 50%")과 일치시키기 위함 |
