# 004. 숨겨진 해금 조건 & 반복 숙련 카드

> ## ⏸ 보류 — 지금은 안 합니다
>
> 이건 **런과 런 사이**의 재미인데, 지금 필요한 것은 **한 런 안**의
> 재미입니다. 한 런이 재미있어야 반복할 이유가 생기고, 그때 비로소
> 누적 해금이 의미를 갖습니다. 순서가 반대면 아무도 두 번째 런을
> 시작하지 않습니다.

> 상태: 🌱 씨앗 | 적은 날: 2026-09-04
>
> 용어는 [002 용어 정본](002-murim-theme.md)을 따릅니다 — 기세 · 아/적 · 틈 · 파훼.

## 한 줄로

카드를 **런을 넘어 누적해서** 쓰면 그 카드의 상위 초식이 열리고, 그 끝에는
아무도 안 알려주는 조건으로만 열리는 카드가 숨어 있다.

## 왜 이게 떠올랐나

무협에서 가장 강한 클리셰 중 하나가 **"기본기 하나를 백만 번 수련한 자"**
입니다. 웹툰/웹소설 『멸망 이후의 세계』의 주인공 재환은 '찌르기'라는 기본
공격만으로 탑을 오른 캐릭터고, 작중에 "찌르기 백만 번" 수련이 등장합니다
(웹 검색 기준 — 원작 확인 필요).

로그라이크의 메타 진행과 이 클리셰가 정확히 겹칩니다. **런에서 진 것도
수련이 됩니다.** 지금 이 게임에는 런과 런 사이에 남는 것이 아무것도 없어서,
20번째 런과 1번째 런이 완전히 같습니다.

## 어떻게 동작하나

### 4-1. 두 개의 축 — 섞으면 안 됩니다

| | **수련(修練)** | **깨달음(頓悟)** |
| --- | --- | --- |
| 조건 | 누적 사용 횟수 | 숨겨진 조건 |
| 진척도 | **보임** (`찌르기 372 / 1000`) | 안 보임 |
| 재미 | 목표 · 성실함의 보상 | 발견 · 소문 |
| 강도 | 완만한 상향 | 이질적인 카드 |
| 카드 경지 ([002](002-murim-theme.md)) | 티어1~3 | 현경 · 생사경 |

두 축을 섞으면(= 숨겨진 조건인데 진척도가 보이면) 둘 다 죽습니다. 수련은
**보여야** 다음 목표가 되고, 깨달음은 **안 보여야** 발견이 됩니다.

### 4-2. 수련 계보 — 찌르기 예시

```text
찌르기          (시작 덱)
  └ 100회  →  강화 찌르기      (보상 풀에 등장)
      └ 1,000회  →  초강화 찌르기
          └ ???  →  차원 찌르기   ← 깨달음 축으로 넘어감
```

무림 작명([002 자료 6](002-murim-theme.md))을 얹으면 계보만으로 경지가
읽힙니다 (스케일이 땅 → 사람 → 하늘 → 천지로 올라가는 4자 규칙):

| 단계 | 임시 이름 | 스케일 |
| --- | --- | --- |
| 기본 | 찌르기 | — |
| 100 | 일점직자(一點直刺) | 한 점 |
| 1,000 | 만인관일(萬人貫一) | 사람 |
| 히든 | 파공관천(破空貫天) | 하늘 |

**숫자는 카드마다 달라야 합니다.** 기본기일수록 임계를 낮게(100/1,000),
고티어 카드일수록 높게 잡으면 안 됩니다 — 반대입니다. 고티어 카드는
애초에 손에 덜 들어오므로 **임계를 낮게** 잡아야 같은 체감 기간이 나옵니다.

### 4-3. 양의 피드백 함정

> 자주 쓰는 카드가 더 강해진다 → 그 카드를 더 자주 쓴다 → 더 강해진다

이걸 그대로 두면 20런째에는 모두가 같은 한 덱을 씁니다. 완화책 세 가지:

1. **해금 = 카드 획득이 아니라 "보상 풀 등장"**. 열려도 런에서 뽑아야
   합니다. 강해지는 건 *덱*이 아니라 *가능성*입니다.
2. **상위 초식은 상위 코스트**. 강화 찌르기가 찌르기보다 세면서 코스트도
   높으면, 덱에 넣을지가 여전히 선택으로 남습니다 (틈을 더 준다는 뜻이므로).
3. **카운트는 카드별로 독립**. 컬러 단위로 묶으면 한 컬러만 파는 게 최적이
   됩니다.

### 4-4. 깨달음 — 숨겨진 조건 카탈로그

| 유형 | 조건 예시 | 어울리는 보상 |
| --- | --- | --- |
| 누적형 | 한 초식을 10,000회 사용 | 그 초식의 최종형 |
| 극단형 | 한 런 내내 방어 카드를 0장 사용하고 클리어 | 살수 계열 (방어 불가, 화력 극대) |
| 정밀형 | 기세를 **정확히 `0`** 에 안착시키기 누적 50회 | 무당 계열 (사량발천근 — 되감기 특화) |
| 자해형 | HP 10% 이하로 스테이지 클리어 | 배수진 (HP가 낮을수록 강함) |
| 절제형 | 한 턴에 카드 1장만 내고 전투 승리 | 일격필살 (턴에 1장만 낼 수 있으나 초고화력) |
| 파훼형 | 한 런에서 파훼 10회 | 파훼 임계점(`적max`)을 상시 낮추는 초식 |
| **패배형** | **같은 적에게 3번 패배** | **그 적의 무공** |

정밀형이 특히 이 게임에만 가능한 조건입니다 — "정확히 0에 안착"은
[8-1](../gdd/08-boss-skill-loop.md)의 중립 규칙을 이해한 사람만 노릴 수
있어서, **조건 자체가 규칙 교육**이 됩니다.

패배형은 로그라이크에서 가장 값싼 위로입니다. 무협 서사와도 맞습니다 —
세 번 지고 그 무공을 파훼하는 법을 깨닫는 것은 클리셰 그 자체입니다.

### 4-5. 발견 가능성 — 완전 히든은 아무도 못 찾습니다

3단계로 열어 줍니다.

| 진척 | 도감 표시 |
| --- | --- |
| 0% | 빈 칸. 존재조차 안 보임 |
| 1~99% | **실루엣 + 구결 한 줄** — "『허(虛)를 아는 자만이 실(實)에 이른다』" |
| 100% | 해금 |

중간 단계가 "구결의 일부를 얻었다"는 무협 장치와 그대로 맞아떨어집니다.
힌트는 조건을 **직역하지 않되** 방향은 알려줘야 합니다 — 위 예시는
정밀형(허초/중립 안착)을 가리킵니다.

## 기존 시스템과 충돌하는 곳

**가장 큰 문제: 이 게임에는 저장이 없습니다.** 런 간 누적은 계정 단위
저장을 요구하고, 그건 웹 데모에 없는 개념입니다.

최소 스키마 초안 (`localStorage`, 키 하나):

```typescript
interface Profile {
  version: 1;
  runsPlayed: number;
  cardUses: Record<string, number>;   // cardKey → 누적 사용 횟수
  unlocks: string[];                  // 해금된 cardKey 목록
  progress: Record<string, number>;   // 깨달음 조건 key → 누적값
}
```

- `cardUses`의 키는 `web-demo/data.js`의 카드 `key`(영문)여야 합니다 —
  [002](002-murim-theme.md)에서 이름을 무림식으로 바꿔도 저장이 깨지지
  않도록.
- `version` 필드는 지금 넣어야 합니다. 나중에 넣으면 이미 저장된 프로필을
  버려야 합니다.
- 카드 목록이 바뀌어 사라진 `key`가 `cardUses`에 남는 건 무해합니다.
  **지우지 말 것** — 카드가 부활했을 때 진척도가 살아납니다.

그 외:

- [09-run-structure.md](../gdd/09-run-structure.md)의 보상 풀이 **고정
  목록에서 프로필 의존으로** 바뀝니다. 신규 플레이어와 20런째 플레이어의
  보상 풀이 달라지므로, 밸런싱 기준선을 "해금 0개 상태"로 잡아야 합니다.
- 도감/진척도 UI가 새로 필요합니다. 전투 화면과 별개 화면입니다.

## 검증하려면

1. **임계값 캘리브레이션** — `web-demo/sim.js`로 자동 플레이를 100런 돌려
   카드별 실제 사용 횟수를 세어 봅니다. "1,000회"가 몇 런에 해당하는지
   모르면 숫자를 정할 수 없습니다. 체감 목표는 *100회 = 몇 런 안에*,
   *1,000회 = 수십 런*, *히든 = 일부러 노려야 도달*.
2. **4-3의 함정이 실제로 나타나는가** — 해금을 전부 켠 프로필과 끈 프로필의
   승률 차이를 잽니다. 차이가 크면 해금이 난이도를 대신 낮추고 있다는 뜻이라,
   보상이 아니라 **선택지**로 다시 설계해야 합니다.
3. **정밀형 조건이 실제로 달성 가능한가** — 자동 플레이에서 "정확히 0 안착"이
   런당 몇 번 일어나는지. 0에 가까우면 조건이 아니라 벽입니다.
