# gdd 정합성 검사

`gdd/`가 **스스로 선언한 정본**과 다른 곳을 찾습니다. 새 등록부 파일은 만들지
않습니다 — 기준은 이미 문서에 적혀 있습니다.

| 무엇 | 정본 |
| --- | --- |
| 용어 | `gdd/12-murim-terms.md` 12-2 |
| 데이터 필드 | `gdd/05-mvp-spec.md` 5-1 |
| 카드 목록 | `gdd/11-card-tiers.md` (이름·수치는 `web-demo/data.js`) |
| 적 수치 | `web-demo/data.js`의 `ENEMIES` (`gdd/10`이 위임) |

`ideanote/` 본문은 검사하지 않습니다 — 미확정이라 gdd와 다른 게 정상입니다.
노트는 G에서 **상태 줄과 졸업 링크만** 읽습니다.

## 1. 기계 검사 — 스크립트를 돌린다

```bash
node .claude/skills/gdd-check/check.js            # 전체
node .claude/skills/gdd-check/check.js 02 10      # 장 지정 (A·C·D·E만, 줄 단위로 펼쳐 보임)
node .claude/skills/gdd-check/check.js --all      # ⚠️ 딱지 절 안의 건까지 전부
```

`$ARGUMENTS`가 있으면 그대로 넘깁니다. 스크립트가 맡는 것:

| | 검사 | 등급 |
| --- | --- | --- |
| **A** | 12-2의 옛 표기가 gdd · 루트 README · web-demo **표시 문자열**에 남았나. 백틱 안 영문 식별자(`cost`, `STARTING_GAUGE`)는 예외, 코드 블록은 한글 주석만 본다 | 🟡 |
| **C** | data.js 상수 이름(`` `STAGE_HEAL_RATIO` ``)과 숫자가 한 줄에 같이 있으면 값 대조 | 🔴 |
| **D** | `\[초식명\]` · `` `한글이름` ``이 data.js에 있나 / gdd/10 적 표(순서·빈틈·클로저·경지) ↔ `ENEMIES` / 표 안의 "빈틈 N~M" 범위 | 🔴 · 🟡 |
| **E** | 깨진 파일 링크, `8-4-4` 같은 절 번호가 그 장 제목에 있나, web-demo 주석의 `gdd/NN N-N` | 🟡 |
| **F** | gdd/00 목차 표 ↔ 실제 파일 · 순서 | 🟡 |
| **G** | "ideanote/NNN에서 졸업" 장 ↔ 그 노트 상태(✅/🔶)와 되돌림 링크, ✅ 노트인데 gdd 링크 없음 | 🟡 |

**⚠️ 딱지 절.** 제목 바로 아래 첫 줄이 `> ⚠️`로 시작하는 절은 스스로 낡았다고
밝힌 곳입니다(예: gdd/11 11-4). 그 안의 건은 숨기고 **건수만** 보고합니다.

**일부러 남긴 곳**은 그 줄 끝이나 바로 윗줄에 `<!-- gdd-check: 무시 -->`를
달면 모든 검사에서 빠집니다. 이 표시는 사용자가 승인했을 때만 답니다.

## 2. 판단 검사 B — 규칙 문장 모순

스크립트가 못 하는 일입니다. **같은 규칙을 두 곳 이상에서 서술한 문장**을
모아 서로 다른 말을 하는지 봅니다.

1. 아래 규칙마다 Grep으로 `gdd/*.md`와 루트 `README.md`에서 서술 문장을 모은다.
   - 파훼 판정 (빈틈을 "넘으면" / "이상이면" — 경계값 포함 여부)
   - 선이 넘어가는 조건 (`0` 초과 / 이상) — 12-2의 "턴이 넘어가는 사건" 행도 여기서 본다
   - 돌아오는 기세 (클로저 성격, 최소 `아3` 보장)
   - 숨 고르기 비용 · 손패 보충 · 연환 드로우
   - 파훼 뒤 효과 (무너짐 기간, 사혈 노출 배율)
   - 검사 대상 장에서 새로 보이는, 두 장 이상에 서술된 규칙
2. 문장끼리 다르면, `web-demo/engine.js`가 실제로 어느 쪽으로 동작하는지
   **참고로만** 확인한다(예: `>=`인가 `>`인가). 코드는 정본이 아니다 —
   어느 쪽이 맞는지는 정하지 않는다.
3. 문장이 하나뿐이거나 비교할 서술이 없으면 그 규칙은 ⚪ 평가 불가.

규칙을 파일 전체로 읽지 말고 Grep으로 찾은 줄 주변만 Read(offset/limit)한다.

## 3. 보고

채팅으로만 보고합니다. **보고서 파일은 만들지 않습니다** — 두 세션이
`main`에 바로 올리는 구조라 파일이 쌓이면 충돌 거리만 늘어납니다.

```
## gdd 정합성 검사 — <범위>
판정: 모순 있음 | 낡음만 있음 | 깨끗함 | 평가 불가
🔴 n · 🟡 n · ⚪ n · ⚠️ 숨김 n

### 🔴 모순 (B · C · D)
- `파일:줄` ↔ `파일:줄` — 무엇이 어떻게 다른가. 엔진은 어느 쪽. 선택지 두세 개
### 🟡 낡음 (A · E · F · G)
- 스크립트 출력을 그대로 — A는 파일별 묶음
### ⚪ 평가 불가
- 무엇을 못 쟀고 왜 (입력 없음 · 비교 상대 없음 · 규칙 없는 용어 행)
```

- **판정 "깨끗함"은 비교한 것이 하나라도 있을 때만**. 비교 대상이 0이면
  "평가 불가"가 정답이고, 그것도 성공한 결과입니다. 빈 검사를 통과로 쓰지
  않습니다.
- 모든 건에 `파일:줄`을 단다. 막연한 경고는 쓰지 않는다.
- 🔴는 **어느 쪽이 맞는지 정하지 않고** 선택지만 낸다.

## 4. 고치기 — 승인한 건만, 세션 경계를 지켜서

검사는 아무것도 고치지 않습니다. 보고 뒤 사용자가 고르면 그 건만 고칩니다.

- **gdd를 고치는 건 데모 세션입니다**(ideanote/00-README "노트 → 파일럿 → 졸업").
  아이디어 세션에서 돌렸다면 보고만 하고, gdd 수정은 데모 세션으로 넘깁니다.
- 🔴이 "구조를 바꿔야 한다"로 이어지면 아이디어 세션 몫입니다.
- 12-2에 행이 늘어 ⚪ "검사 규칙이 없다"가 나오면 `check.js`의
  `OLD_TERM_RULES`에 정규식을 더합니다.
