# 8. 적 초식 루프 (Boss Skill Loop)

보스는 플레이어처럼 **비용이 있는 기술 목록**을 가지고, 게이지가 음수가
될 때까지 기술을 반복 사용합니다. 플레이어 턴 종료 규칙과 대칭입니다.

## 8-1. 대칭 규칙

| | 플레이어 턴 | 적 페이즈 |
| --- | --- | --- |
| 진행 | 카드를 낼 때마다 비용만큼 게이지가 **오른쪽(+)** 으로 이동 | 기술을 쓸 때마다 비용만큼 게이지가 **왼쪽(-)** 으로 이동 |
| 종료 조건 | 게이지가 `0`을 **초과**(양수)해야 종료 | 게이지가 `0` **미만**(음수)이어야 종료 |
| 정확히 0 | 중립 — 계속 진행 (턴이 끝나지 않음) | 중립 — 계속 진행 (페이즈가 끝나지 않음) |

"정확히 0에서는 그 누구의 턴도 끝나지 않는다"는 규칙이 양쪽에 동일하게
적용됩니다. 보스가 최소 한 번은 반드시 행동하도록, 비용 1의 `일반 공격`은
쿨다운 없이 항상 사용 가능합니다.

## 8-2. 보스 기술 목록

스테이지별 기술 구성과 수치는 [10-enemy-roster.md](10-enemy-roster.md)가
정본입니다. 이 문서는 규칙만 정의합니다.

- 기술 비용은 항상 `1~5` — 게이지의 유효 진입 최대값이 `적5`이기 때문입니다
  (`적max`은 파훼로 별도 처리, [02-boss-intent-thresholds.md](02-boss-intent-thresholds.md)).
- 모든 적은 비용 1·쿨다운 0의 기본 공격을 하나씩 가집니다 — 없으면 게이지가
  정확히 `0`일 때 루프가 종료되지 못합니다.

## 8-3. 쿨다운 규칙

- 기술을 사용하면 `bossCooldowns[기술] = 그 기술의 쿨다운 값`으로 설정됩니다.
- **매 적 페이즈 시작 시** (기술을 하나라도 쓰기 전), 쿨다운이 남은 모든
  기술의 값을 1씩 감소시킵니다 (0 미만으로는 내려가지 않음).
- 쿨다운이 0인 기술만 사용할 수 있습니다.
- 같은 페이즈 안에서 방금 쓴 기술은 쿨다운이 즉시 설정되므로, 한 페이즈
  안에서 같은 기술을 두 번 연속 쓸 수 없습니다.

## 8-4. 보스 행동 선택 — 오프너와 클로저

보스의 한 페이즈는 **오프너(들) + 클로저** 구조입니다. 이 구분이 이
시스템에서 가장 중요한 규칙입니다.

- **오프너 (예산 안에 드는 분기):** 쿨다운이 0이면서 비용이 현재 게이지
  이하인 기술 중 우선순위가 가장 높은 것을 씁니다. 이 분기는
  `게이지 − 비용 ≥ 0`이므로 **페이즈를 끝내지 못합니다.**
- **클로저 (예산 안에 드는 게 없을 때):** 쿨다운이 0인 기술 중 **비용이
  가장 비싼 것**을 씁니다 (동률이면 우선순위). 페이즈를 끝내는 것은 항상
  이 분기이므로, **여기서 무엇을 고르느냐가 플레이어에게 돌아가는 기세
  양을 결정합니다.**

이 구조가 만드는 결과가 핵심입니다 — **작게 넘길수록 큰 기술이 안 쓰인 채
남아 있어, 그게 클로저로 나가면서 그만큼 깊은 버퍼를 돌려줍니다.**
`적1`으로 살짝 넘기면 오프너로 일반 공격 한 번(게이지 0) → 클로저로 광역
강타(비용 5) → 플레이어는 `아5`에서 다음 턴을 시작합니다. "보스가 크게
때린 만큼 나에게 크게 돌아온다"가 규칙 자체에서 나옵니다.

> **왜 클로저를 "가장 싼 것"으로만 하면 안 되는가:** 초기 구현이 그랬는데,
> 비용 1짜리 기본 공격이 항상 후보에 있으므로 마지막 행동이 언제나
> "게이지 0에서 비용 1" → 착지 `아1`로 고정됐습니다. 플레이어는 매 턴
> 카드를 한 장밖에 못 내 덱 빌드업 자체가 성립하지 않았습니다.
> 아래 8-4-1의 노회형은 **8-4-4의 최소 반환 보장을 반드시 유지한 채로만**
> 성립합니다. 보장이 없으면 그때 그 실패가 그대로 재현됩니다.

### 8-4-1. 클로저 성격 — 패도와 노회

클로저를 무엇으로 고르는지는 **적의 성격(`closerStyle`)**입니다. 적마다
다르며, [10-enemy-roster.md](10-enemy-roster.md)가 정본입니다.

| 성격 | 클로저 선택 | 플레이어가 받는 문제 |
| --- | --- | --- |
| **패도(覇道)** | 준비된 초식 중 **가장 비싼 것** | 크게 맞고 크게 돌려받는다 |
| **노회(老獪)** | 예산을 넘기는 것 중 **가장 싼 것** | 덜 맞지만 다음 합이 짧다 |

"일격은 포기하되 틈을 적게 준다"가 노회형입니다. 무림 고수의 운영 그
자체이고, 플레이어에게는 **완전히 다른 문제**를 냅니다.

- **패도형 상대로는 살짝 넘기는 것이 정답입니다.** 큰 초식이 클로저로
  나가면서 깊은 버퍼가 돌아오니까요.
- **노회형 상대로는 살짝 넘겨도 돌아오는 게 최소 보장(`아3`)뿐입니다.**
  버퍼를 쌓아 연계를 터뜨리는 플레이가 막히므로, **아예 파훼를 노리거나
  짧은 합을 반복하는 쪽으로 전술을 갈아타야 합니다.**

즉 이 스탯은 난이도가 아니라 **플레이어에게 요구하는 전술**을 바꿉니다.
`적max`(2-2)가 "파훼가 얼마나 현실적인가"를 정하고 `closerStyle`이
"버퍼 축적이 통하는가"를 정하므로, 둘을 조합하면 네 종류의 서로 다른
싸움이 나옵니다.

| | 패도 | 노회 |
| --- | --- | --- |
| **낮은 `적max`** | 가장 쉬움 — 파훼도 버퍼도 다 통함 | 파훼 특화. 버퍼는 포기 |
| **높은 `적max`** | 정면 승부. 버퍼로 화력을 쌓아 정공법 | 가장 어려움 — 둘 다 막힘 |

### 8-4-2. 클로저는 방어도를 관통한다

**페이즈를 끝내는 마무리 일격은 방어도를 절반만 인정합니다**
(`인정되는 방어도 = floor(방어도 / 2)`). 오프너는 그대로 전부 막힙니다.

이 규칙이 없으면 8-4 전체가 무력해집니다. "작게 넘기면 큰 초식이 마무리로
온다"는 구조는 **그 큰 초식이 실제로 아프다는 전제** 위에 서 있는데,
방어도가 통째로 먹으면 얕은 착지가 그냥 안전한 선택이 됩니다.

> 실측이 정확히 그랬습니다. 관통 전 백(白)은 **합의 75%를 `적2`에 착지시키고
> 거기서 평균 0.8 피해만 받았습니다**(적(赤)은 `적3`에서 6.6). 방어도 수치를
> 30% 깎아도, 반탄을 지워도, 임계점 조작을 지워도 클리어율이 93%에서
> 움직이지 않았습니다 — 어떤 개별 수치의 문제가 아니라 **시소 규칙이
> 한 문파에게만 꺼져 있던 것**이었습니다. 관통을 넣자 93% → 35%가 됐고,
> 그 뒤로는 방어도 수치를 되돌려도 거의 움직이지 않습니다.

**흘리기(`evade`)는 관통보다 먼저 판정되어 클로저도 통째로 넘깁니다.**
방어도가 큰 일격에 약하고 흘리기가 큰 일격에 강한 것이 두 경감 수단의
성격 차이입니다 ([11-3](11-card-tiers.md)).

### 8-4-3. 연속 사용 시 비용 증가

같은 기술을 바로 이어서 쓸 때마다 그 기술의 비용이 1씩 오릅니다 (예:
일반 공격을 연달아 쓰면 `1 → 2 → 3`). 다른 기술이 끼어들면 리셋되고,
이 카운트는 적 페이즈가 끝나면 사라집니다(페이즈 로컬). 저비용 기술을
계속 연타하는 지루한 패턴을 억제합니다.

최종 비용 = `max(1, 기본 비용 + 연속 사용 가산)`

### 8-4-4. 최소 반환 보장

적 페이즈가 끝난 뒤 최종 게이지가 `아3`보다 얕으면 **`아3`으로 보정**
합니다 (`gauge = clamp(min(finalGauge, -3), -6, ...)`). 큰 기술이 전부
쿨다운이라 클로저가 작을 수밖에 없는 페이즈에서도 플레이어가 최소 3
기세는 확보하게 하는 바닥입니다. 그보다 깊은 착지(`아4`~`아6`)는 보정
없이 그대로 통과하므로 8-4의 상방 변동성은 유지됩니다.

**기절 페이즈에도 동일하게 적용됩니다.** 안 그러면 파훼 직후 기절 턴에
오히려 가장 얕은 반환이 나오는 최악의 경우가 생깁니다.

## 8-5. 진행 예시

플레이어가 `적2`로 턴을 종료한 상황 (실제 실행 로그):

```
게이지가 E2(으)로 넘어가 턴이 종료됩니다.
[동력 충전](비용 2) 사용 — 공격력 +2, 방어도 +6.      ← 오프너 (비용 2 ≤ 게이지 2)
[광역 강타](비용 5) 사용 — 18 피해. 취약 부여.         ← 클로저 (예산 초과, 가장 비싼 것)
적 페이즈 종료 — 게이지 P5에서 플레이어 턴이 시작됩니다.
```

## 8-6. 기절(Stun)·파훼와의 관계

- **파훼**(`적max` 도달)는 이 루프보다 먼저 판정되며, 루프 자체가 시작되지
  않습니다 ([02-boss-intent-thresholds.md](02-boss-intent-thresholds.md)).
- **기절 상태**의 페이즈는 기술을 전혀 사용하지 못합니다(루프 0회 실행).
  쿨다운도 그 페이즈 동안은 갱신되지 않습니다 — "얼어붙은 턴"으로
  취급합니다. 게이지는 `P(n)`으로 이동하되 8-4-4의 최소 반환 보장을
  받습니다.

## 8-7. 실시간 인텐트 미리보기

플레이어 턴 중 게이지가 양수인 동안, "지금 턴을 종료하면 어떻게 되는지"를
실제 기술 루프를 **부작용 없이 시뮬레이션**해서 보여줍니다 (쿨다운·연속
사용 카운트는 복사본으로 굴리고 실제 상태는 건드리지 않으며, 8-4-2의
보정까지 동일하게 적용해 예고 위치와 실제 결과가 일치합니다). 각 단계에는
기술이 소모하는 비용(=넘겨줄 기세)도 함께 표시하고, 기술 목록 UI에는
모든 기술의 비용과 쿨다운 상태를 상시 노출합니다.

> **미리보기의 한계:** 각 기술의 기본 피해(+누적 공격력)만 계산하며, 같은
> 페이즈 안에서 앞선 공격이 건 취약(+50%)을 뒤따르는 공격이 소모하는 연쇄
> 보너스는 반영하지 않습니다 — 실제 피해가 예고보다 높게 나올 수 있습니다.
> 최종 게이지 위치는 정확합니다.

## 8-8. 데이터 모델

```typescript
interface BossSkill {
  key: string;
  name: string;
  cost: number;         // 1~5
  kind: 'ATTACK' | 'ATTACK_WEAKEN' | 'ATTACK_VULNERABLE' | 'BUFF';
  damage?: number;      // ATTACK* 종류
  powerGain?: number;   // BUFF
  blockGain?: number;   // BUFF
  cooldown: number;     // 0 = 쿨다운 없음
  priority: number;     // 높을수록 우선 선택 (오프너 분기에서 사용)
}
```

`BattleState`의 보스 관련 필드는 [05-mvp-spec.md](05-mvp-spec.md) 5-1의
스키마를 참고하세요. 연속 사용 카운트(8-4-3)는 페이즈 하나를 처리하는
동안에만 쓰고 버리는 루프 로컬 상태라 `BattleState`에 저장하지 않습니다.
