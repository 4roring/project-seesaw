# 005. 초식 연환 — 특정 순서로 터지는 강제 발동 절초

## 한 줄로

카드를 **정해진 순서로** 냈을 때 절초 한 장이 **자동으로 터지고**, 그
절초도 제 몫의 기세를 먹는다.

## 왜 이게 떠올랐나

현재 [콤보 드로우](../gdd/07-turn-economy-revision.md)(7-3)는 카드를 3장
쓰면 1장을 뽑아 주는데, **무엇을 냈는지는 보지 않고 몇 장을 냈는지만**
봅니다. 레드의 연계(`chain`)도 마찬가지로 "이번 턴에 몇 장 썼나"만 셉니다.
즉 이 게임에는 아직 **순서를 아는 규칙이 없습니다** — 순서가 피해량을
정할 뿐, 순서 자체가 조건이 된 적은 없습니다.

무협에서 초식은 원래 이어져 있습니다([002 자료 3](002-murim-theme.md)) —
심법으로 쌓고, 초식으로 무너뜨리고, **절초로 마무리**합니다. 절초가 덱에
처음부터 들어 있는 것보다, 앞의 초식을 제대로 이었을 때만 나오는 쪽이
훨씬 그럴듯합니다. 그리고 연환 초식은 **멈추려 해도 멈춰지지 않는 것**이
자연스럽습니다 — 그래서 손에 들어와 기다리는 카드가 아니라 강제 발동입니다.

## 어떻게 동작하나

### 5-1. 레시피와 강제 발동

```text
[매화점점] → [매화난만] → [낙매분분]  ...  세 초식을 이 순서로 냈다
                                        ↓
                         [매화만개] 자동 발동 — 비용도 함께 지불
```

- 레시피는 카드 `key`의 나열입니다.
- 마지막 카드를 사용한 **직후** 절초가 스스로 발동합니다. 플레이어가
  누를 것은 없습니다.
- 절초는 덱에 속하지 않고, 발동 후 소멸합니다.
- **절초도 비용을 냅니다.** 그만큼 기세가 보스 쪽으로 더 밀립니다.

### 5-2. "순서"를 어떻게 판정할까

| 판정 | 뜻 | 성격 |
| --- | --- | --- |
| **연속(접미사 일치)** | 직전 3장이 정확히 그 순서 | 엄격. 중간에 딴 카드를 끼우면 실패 |
| 포함(순서만 유지) | 이번 턴에 A→B→C 순으로 나오기만 하면 됨 (사이에 다른 카드 허용) | 느슨. 대충 내도 터짐 |

**연속을 권합니다.** 느슨하게 하면 "긴 턴에는 저절로 터지는 것"이 되어
콤보 드로우와 구분이 사라집니다. 연속이면 플레이어가 **손패 순서를 짜는
문제**가 생기고, 그게 [7-2 핸드 유지](../gdd/07-turn-economy-revision.md)
규칙(안 쓴 카드가 손에 남는다)과 정확히 맞물립니다 — 이번 턴에 안 쓰고
쥐고 있다가 다음 턴에 순서를 맞추는 플레이가 처음으로 의미를 갖습니다.

### 5-3. 강제 발동이 두 문제를 동시에 없앱니다

초안에서 가장 큰 걸림돌은 **"절초를 만들자마자 턴이 끝나 못 쓴다"**
였습니다. 시퀀스 3장을 다 내면 기세가 이미 바닥이라, 손에 들어온 절초가
쓰이지도 못하고 사라지는 문제입니다. 강제 발동은 이걸 **규칙을 추가하지
않고** 없앱니다.

**이 게임은 이미 "카드의 모든 처리가 끝난 뒤에 턴이 넘어간다"로 동작합니다.**
`engine.js`의 `playCard`는 피해·방어·지속효과·콤보 드로우·승패 판정을 전부
끝낸 **다음에야** 기세를 갱신하고 턴 종료를 판정합니다
([engine.js:503-527](../web-demo/engine.js)). 디지몬 TCG에서 메모리가 넘어가도
진행 중인 처리가 전부 끝난 뒤에 턴이 넘어가는 것과 같은 구조입니다.

그러므로 절초는 **예외가 아니라 그 처리의 일부**입니다. 초안 5-3에서 고민한
네 가지 우회안(코스트 0 / 턴 종료 유예 / 되감기 / 다음 턴 지급)이 전부
필요 없어집니다. 특히 "턴 종료 유예"는
[7-1](../gdd/07-turn-economy-revision.md)이 패스를 없애며 어렵게 세운
"예외 없는 턴 종료 규칙"에 구멍을 뚫는 안이었는데, 그걸 뚫지 않아도 됩니다.

**그리고 소멸 규칙 자체가 없어집니다.** 절초가 손에 머무는 시간이 0이므로
"안 쓰면 사라진다"는 상태가 존재하지 않습니다. 카드 플래그 하나, UI 상태
하나가 통째로 사라집니다.

### 5-4. 비용이 곧 밸런스 장치입니다

"결국 이것만 쓰게 되지 않을까"에 대한 답이 **절초가 기세를 먹는다**는
설정 안에 이미 들어 있습니다. [8-4](../gdd/08-boss-skill-loop.md)의 규칙
때문입니다.

```text
시퀀스 3장으로 적1 착지  →  보스가 큰 클로저로 마무리  →  아5로 복귀 (깊은 버퍼)
     + 절초(비용 3)     →  적4 착지  →  보스가 예산 안에서 여러 번 때리고
                                        작은 클로저로 마감  →  아2 복귀 (얕은 버퍼)
```

**절초를 터뜨린 대가는 피해량이 아니라 "다음 턴이 짧아지는 것"입니다.**
"작게 넘길수록 크게 돌아온다"는 기존 원리가 그대로 브레이크 역할을 합니다 —
따로 페널티를 설계할 필요가 없습니다. 이게 이 안의 가장 좋은 점입니다.

부수 효과 둘:

- **파훼(BREAK)를 절초로 노릴 수 있습니다.** 절초의 비용까지 계산해서
  `적6`에 정확히 꽂는 플레이가 생깁니다. "연환 초식의 마지막 한 수로 상대의
  균형을 깬다"는 [002](002-murim-theme.md)의 파훼 개념과 정확히 맞습니다.
- **거꾸로, 파훼를 노리던 계산을 절초가 망칠 수 있습니다.** `적6`을 맞추려고
  짠 순서가 우연히 레시피와 일치하면 절초가 끼어들어 `적6`을 지나쳐 버립니다.
  → 5-6의 표시가 없으면 이건 그냥 버그처럼 보입니다.

### 5-5. 발동 타이밍 — 즉시 vs 턴 이양 직전

| 안 | 타이밍 | 결과 |
| --- | --- | --- |
| **즉시** | 트리거 카드의 비용이 반영된 직후 | 기세에 여유가 있으면 **턴이 안 끝납니다.** 절초를 쓰고도 계속 플레이 |
| 이양 직전 | 기세가 `0`을 넘어 턴을 넘기기 직전에 예약 발동 | 언제 완성하든 결과가 같음. 항상 착지가 깊어짐 |

**즉시를 권합니다.** 이양 직전 안은 절초가 항상 "마지막에 붙는 세금"이지만,
즉시 안은 **깊은 버퍼를 받은 턴에 시퀀스를 완성하라**는 새로운 목표를
만듭니다 — `아5`에서 시퀀스를 완성하면 절초를 터뜨리고도 턴이 이어지고,
`아2`에서 완성하면 절초와 함께 턴이 끝납니다. 같은 레시피가 기세 상황에
따라 다른 값을 갖게 되고, 그게 이 게임의 핵심 축과 같은 방향입니다.

### 5-6. 보이지 않으면 사고가 됩니다

초안에서는 "안 보이면 우연이 된다"가 문제였는데, 강제 발동에서는 더
심각해집니다 — **모르는 사이에 턴이 끝날 수 있습니다.** 최소한:

- 손패에서 **지금 내면 시퀀스가 진행되는 카드**에 테두리 강조
- 진행 중일 때 콤보 도트 옆에 `매화검법 2/3` 진척 표시
- **마지막 한 장을 내기 전에 결과 예고** — "발동 시 절초(비용 3)까지
  자동 사용 → `적4` 착지". 기존 인텐트 미리보기([8-7](../gdd/08-boss-skill-loop.md))가
  이미 "지금 끝내면 어떻게 되는지"를 계산하고 있으니, 여기에 절초 비용만
  더하면 됩니다.
- 끊겼을 때 한 줄 로그 — 왜 안 터졌는지 모르는 게 제일 나쁩니다

## 기존 시스템과 충돌하는 곳

### ⚠️ 처리 순서 — 턴 종료 판정이 두 번 돌 수 있습니다

현재 `playCard`는 `[효과 → 콤보 드로우 → 승패 판정 → 기세(`game.gauge`) 갱신 → 턴 종료
판정]` 순입니다. 절초를 **콤보 드로우 자리에서** 발동시키면 트리거 카드의
비용이 아직 반영되기 전이라 잘못된 기세로 계산하고, **기세 갱신
자리에서** 발동시키면 `endPlayerTurnAndResolveBoss`가 두 번 호출될 수
있습니다.

올바른 순서는 하나뿐입니다:

```text
트리거 카드 효과 → 콤보 드로우 → 트리거 카드 비용을 기세에 반영
  → [대기 중인 강제 발동을 전부 소진] → 승패 판정 → 턴 종료 판정 (한 번만)
```

즉 강제 발동은 **큐**로 두고, 큐가 빈 뒤에 딱 한 번 종료를 판정해야 합니다.
"넘어가면서 모든 행동이 끝나야 턴을 넘긴다"를 코드로 옮기면 이 모양입니다.
절초가 또 다른 시퀀스를 완성시키는 경우(5-7)까지 생각하면 큐가 아니라
루프여야 합니다.

### 손패 수는 이제 안전합니다

초안에서는 절초를 손에 넣어 쓰면 `cardsPlayedThisTurn`이 늘어 다음 턴
보충 드로우가 한 장 더 나가는 문제가 있었습니다
([7-2](../gdd/07-turn-economy-revision.md)). 강제 발동은 손을 거치지 않으므로,
**그 카운터를 아예 건드리지 않으면** 끝입니다. 절초는 `cardsPlayedThisTurn`,
`comboCounter`, `cardsDiscardedThisTurn` 셋 다에 잡히지 않아야 합니다.

### 5-7. 그 밖에

- **절초가 시퀀스를 이어도 되는가.** 되면 연쇄 발동이 열립니다 — 재미있지만
  무한 루프의 문. 절초는 순서 기록(`playedKeysThisTurn`)에 남기지 않는 쪽이
  안전합니다. 나중에 "연환 절초"를 의도적으로 설계할 때 푸는 잠금장치로
  남겨 둡니다.
- **레드의 `chain`과 곱해집니다.** 절초는 정의상 턴 후반에 터지므로
  `cardsPlayedThisTurn`이 이미 큽니다. 절초에 `chain`을 붙이면 피해가 두 배로
  폭주하니, 절초는 고정 수치로 두는 편이 안전합니다.
- **보스가 이미 죽었으면 발동하지 않습니다.** 콤보 드로우가 `bossHp > 0`을
  확인하는 것과 같은 이유입니다 — 끝난 전투에 기세를 더 밀 이유가 없습니다.
- **시퀀스 길이는 3을 피합니다.** 3장이면 콤보 드로우와 같은 지점에서 터져
  무엇 때문에 뭐가 왔는지 안 보입니다(UI 콤보 도트도 3칸). 2장(연환) /
  4장(절초)으로 나누면 두 축이 됩니다.

## 데이터 모델 초안

```typescript
interface ComboRecipe {
  key: string;
  name: string;          // "매화검법" — UI 진척 표시에 쓰임
  sequence: string[];    // 카드 key의 나열. 연속으로 일치해야 발동
  grants: string;        // 강제 발동할 절초의 key
}
```

`BattleState`에 추가되는 것은 하나뿐입니다:

```typescript
playedKeysThisTurn: string[];   // 이번 턴에 낸 카드 key (강제 발동분 제외)
```

판정은 `playedKeysThisTurn`의 **접미사**가 어떤 레시피의 `sequence`와
일치하는지만 보면 됩니다 — 카드 한 장당 레시피 수만큼의 비교라 비용이
없습니다. 절초 카드 정의는 일반 카드와 같되 보상 풀·덱에서 제외합니다.

## 다른 노트와의 연결

- [002 무림 테마](002-murim-theme.md) — "심법 → 초식 → **절초**" 구조가
  이 규칙의 서사입니다. 레시피 이름은 무공명(매화검법), 발동되는 카드는
  그 무공의 절초로 두면 이름 체계가 저절로 정리됩니다.
- [004 숨겨진 해금](004-hidden-card-unlocks.md) — **레시피 자체를 히든으로
  둘 수 있습니다.** 우연히 순서가 맞아 처음 터졌을 때 "무언가를 깨달았다"가
  뜨고, 그 뒤로 도감에 레시피가 기록되는 흐름. 강제 발동이라 **첫 발동이
  반드시 일어난다**는 점이 히든 조건으로서 유리합니다 — 손에 들어와도 안
  쓰고 지나칠 수가 없으니까요.
- [003 합 교환](003-hap-exchange-memory.md) — 가변 `P_max`가 커질수록 5-5의
  "즉시 발동" 안이 유리해집니다. 버퍼가 깊으면 절초를 터뜨리고도 턴이
  이어지므로, `P_max` 성장 자체가 절초 활용도를 올리는 보상이 됩니다.

## 검증하려면

1. **처리 순서가 맞는가** — 시퀀스 완성으로 기세가 `0`을 넘는 상황에서
   `endPlayerTurnAndResolveBoss`가 정확히 한 번만 호출되는지. 위의 큐/루프가
   틀리면 보스가 두 페이즈를 연달아 행동합니다.
2. **5-4의 자동 밸런스가 실제로 작동하는가** — `web-demo/sim.js`에서 절초를
   가진 덱과 없는 덱의 **턴당 피해량**과 **평균 착지 위치**를 함께 잽니다.
   피해량이 오른 만큼 착지가 깊어져 반환이 줄면 설계대로고, 피해량만 오르면
   절초 비용이 너무 쌉니다.
3. **5-5 즉시 발동이 턴을 얼마나 늘리는가** — 시퀀스 완성 시점의 기세 분포를
   재서, "절초를 쓰고도 턴이 이어지는" 비율을 봅니다. 이 비율이 0에 가까우면
   즉시 안과 이양 직전 안이 사실상 같은 것이므로, 단순한 이양 직전 안을
   택하면 됩니다.
4. **파훼 계산을 망치는 빈도** — 5-4의 부수 효과 둘째. 자동 플레이에서
   "절초 때문에 `적6`을 지나친" 횟수를 셉니다.
