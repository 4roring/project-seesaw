# Timeline Seesaw — Web Demo

`gdd/` 폴더의 기획 문서를 기반으로 만든 빌드 도구 없는 순수 HTML/CSS/JS
프로토타입입니다. 무림 4문파(적·흑·백·자)와 스테이지 1~10 런 전체가
플레이 가능합니다. 용어는 [gdd/12](../gdd/12-murim-terms.md)를 따릅니다 —
기세 · 틈 · 아/적 · 합 · 파훼.

## 실행 방법

Node.js 없이도 바로 열 수 있습니다.

```bash
open index.html
```

드래그 앤 드롭(HTML5 Drag and Drop API)이 `file://`에서 정상 동작하지
않는 브라우저도 있으니, 문제가 있으면 로컬 서버로 열어주세요.

```bash
python3 -m http.server 8000
```

이후 브라우저에서 `http://localhost:8000` 접속.

## 구현 범위

**스테이지 1~10 런 전체**가 플레이 가능합니다 — 4색 덱 선택 → 전투 →
보상(새 카드 / 카드 강화) → 회복 → 다음 스테이지. 구현된 규칙은 아래
문서들을 그대로 따릅니다.

| 규칙 | 문서 |
| --- | --- |
| 게이지·턴 교대·자원 반환 | [01](../gdd/01-core-system-gauge.md) |
| 파훼 — 한 합의 몰아치기가 적의 빈틈을 넘으면 발동 | [02](../gdd/02-boss-intent-thresholds.md) |
| 적 초식 루프 (오프너/클로저, 클로저 성격, 최소 반환 보장, 인텐트 미리보기) | [08](../gdd/08-boss-skill-loop.md) |
| 지속 효과(심법/진법), "다음 초식 한 장" 보너스 유지 | [06](../gdd/06-persistent-effects.md) |
| 숨 고르기(기세→카드), 핸드 유지형 드로우, 연환 드로우 | [07](../gdd/07-turn-economy-revision.md) |
| 데이터 스키마·승패 조건 | [05](../gdd/05-mvp-spec.md) |
| 런 구조(스테이지 1~10, 덱 10→20장, 스테이지 간 회복) | [09](../gdd/09-run-structure.md) |
| 적 10종 — 개성 두 축과 스테이지 편성 | [10](../gdd/10-enemy-roster.md) |
| 무림 용어·작명·이름 저작권 원칙 | [12](../gdd/12-murim-terms.md) |
| 4문파·경지·강화 | [11](../gdd/11-card-tiers.md) |

UI는 1:1 가로 대전 구도(플레이어 ↔ 적)로, 공격/피격 모션, 스킬명·피해량
플로팅 표시, 게이지 위로 기세가 떨어지는 연출, 파훼 화면 연출,
카드 드래그 앤 드롭, 실시간 적 인텐트 미리보기를 포함합니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `data.js` | 4색 덱·보상 풀·강화표·적 10종·상수 |
| `engine.js` | 전투 엔진 (게이지, 카드 효과, 적 기술 루프) |
| `run.js` | 런 진행 (스테이지, 보상, 회복) |
| `ui.js` | 화면 라우팅·렌더링·연출 |
| `sim.js` | 밸런스 시뮬레이션 하네스 (게임에서 로드하지 않는 개발용) |

### 밸런스 시뮬레이션 돌리는 법

브라우저 콘솔에서:

```javascript
fetch('sim.js').then(r => r.text()).then(eval);
['RED','BLUE','BLACK','YELLOW'].map(c => TS_Sim.run(c, 150));
```

간단한 탐욕 AI로 런을 자동 플레이해 클리어율·평균 도달 스테이지·턴당
카드 사용 수·사망 스테이지 분포를 돌려줍니다. **턴당 카드 사용 수는 무한
루프 탐지기로도 쓰입니다** — 정상값은 2.5~3.8이고, 한 자리를 크게 넘으면
메모리나 손패를 순증시키는 카드 조합이 생겼다는 뜻입니다.

## 밸런스 현황 (자동 플레이 200런 기준)

**클리어율은 버그가 아니라 난이도 표기입니다.** 모든 문파가 같은 승률일
필요는 없고, 낮은 쪽이 "생각을 많이 하고 써야 하는 문파"면 됩니다.

| 문파 | 탐욕 AI | 계획 AI | 계획 상승폭 | 평균 도달 | 합 시작 손패 |
| --- | --- | --- | --- | --- | --- |
| 자(마교) | 79% | 69% | −10%p | 9.7 | 6.9 |
| 흑(무당) | 65% | 60% | −5%p | 9.8 | 6.3 |
| 백(금강사) | 62% | 59% | −3%p | 9.8 | 5.4 |
| 적(화산) | 49% | 59% | **+10%p** | 9.6 | 5.4 |

> 클리어율은 런당 편차가 커서 50~100런으로는 ±20%p까지 흔들립니다.
> 문파를 비교할 때는 200런 이상을 쓰세요.

### "어려운 문파"와 "약한 문파"를 가르는 법

승률만으로는 둘을 구분할 수 없습니다. 그래서 하네스에 **계획형 정책**을
넣었습니다 — 패 파기는 손패가 4장 이상일 때, 연계는 2장 깐 뒤, 흘리기는
겹쳐 쓰지 않는 정도의 사람이 할 법한 판단만 추가한 것입니다.

```javascript
TS_Sim.run('RED', 200, { planned: true })
```

**두 정책의 차이가 곧 그 문파의 "생각할 여지"입니다.** 적(赤)은 +11%p로
순서를 짜면 실제로 보상받는 반면, 나머지는 거의 움직이지 않습니다. 승률이
낮은 문파를 조정할 때 이 값을 먼저 보세요 — **상승폭이 크면 어려운 것이고,
0에 가까우면 그냥 약한 것**이라 조치가 정반대입니다.

이 문서 초기 측정에서는 백 외 세 문파가 클리어율 0%, 평균 도달 6.4~7.3이었습니다.
**네 문파 모두 최종 스테이지권까지 도달**하게 됐지만 클리어율 격차는 남아
있습니다.

### 무엇이 격차를 만들었나

시뮬레이션으로 확인한 순서대로입니다.

1. **화력은 병목이 아니었다.** 고티어 피해를 올려도 백만 올라갔고, 적
   피해를 15% 낮추자 오히려 격차가 벌어졌습니다. 사망 시점의 보스 잔여
   체력은 어느 문파나 15~22%로 비슷했습니다 — 아슬아슬하게 지는 것이지
   화력이 모자란 게 아니었습니다.
2. **문제는 "쌓인 자원을 쓸 출구"의 유무였다.** 문파마다 출구를 하나씩
   주자(적 `chain`/`chainBlock`, 흑 `discardAll`, 백 `blockToDamage`,
   자 `lifesteal`) 해당 문파가 즉시 올라왔습니다. 자(紫)는 `생명 착취`에
   흡혈을 붙인 것만으로 5.8 → 7.5가 됐습니다.
3. **적(赤)은 틈 구조 자체가 문제였다.** 합의 절반을 `적5`로 마감해
   적에게 만점 예산을 넘기고 있었고(합당 피격 4.9 vs 백 0.9), 원인은
   틈 5짜리 피니셔였습니다. 같은 화력을 중간 틈의 연계로 옮기자
   8.1 → 8.8로 올랐습니다.
4. **티어 스케줄이 한 칸 어긋나 있었다.** 스테이지 8을 티어3 카드 없이
   맞고 있어 사망의 절반 이상이 그 한 스테이지에 몰렸습니다. 티어가 열리는
   시점을 한 칸 앞당기자 적·자가 각각 +0.5, +0.7 올랐습니다.
5. **적에게 개성이 없으면 스테이지가 늘어나도 같은 싸움입니다.** 빈틈과
   클로저 성격(패도/노회)을 적 스탯으로 만들자, 같은 엔진에서 네 종류의
   다른 문제가 나왔습니다. 특히 **노회형은 얕게 넘겨도 최소 보장(`아3`)만
   돌려주므로** 버퍼를 쌓는 플레이 자체를 막습니다 — 난이도가 아니라
   전술을 바꾸는 스탯입니다.
6. **빈틈이 작은 적에게는 낮은 HP를 짝지어야 합니다.** 자주 파훼당하는
   적이 HP까지 높으면 소모전이 되어, 버프가 누적되는 쪽에 일방적으로
   유리해집니다. 실제로 그 조합을 줬더니 그 한 스테이지에서 자동 플레이의
   30%가 죽었습니다.
7. **경감 수단은 출구와 별개 축입니다.** 흑(黑)은 화력이 4문파 중 1위(합당 35.7)
   인데도 최하위였는데, 원인은 **합당 방어도 0.1**이었습니다(백은 5.1).
   흘리기(`evade`)를 주자 곧바로 29% → 41%로 올랐습니다.
8. **파훼가 죽어 있었습니다 — 규칙이 서사와 반대로 작동했습니다.**
   파훼율이 0~1%(흑은 0.0%)였고, 가장 잘 무너져야 할 적조차 0.0%였습니다.
   원인은 구조입니다. 합은 기세가 `0`을 넘는 순간 끝나므로 파훼는 늘
   "마지막 한 장의 단독 점프"여야 했고, 필요한 틈은 `빈틈 + 지금 버퍼`
   였습니다 — **버퍼가 깊을수록 파훼가 더 불가능해졌습니다.** "버퍼를 쌓아
   파훼를 노린다"는 원래 서사와 정반대입니다. 판정을 **한 합에 지불한 틈의
   합계**로 바꾸자 0~1% → 6~11%가 됐고, 깊은 버퍼가 처음으로 파훼로
   이어졌습니다 ([gdd/02 2-1](../gdd/02-boss-intent-thresholds.md)).
   부수 효과로 **파훼가 흑(무당)의 전술**이 됐습니다 — 되감기로 합을 늘려
   몰아치기를 쌓는 문파라 파훼율이 10.9%로 압도적입니다.
9. **드로우 초식이 손패를 영구히 불렸습니다.** 보충량에서 연환 드로우는
   빼는데 **드로우 초식으로 뽑은 장수는 안 빼고 있어서**, 드로우 초식 한
   장당 손패가 합마다 +1씩 쌓였습니다. 흑(무당)의 합 시작 손패가 8.5장까지
   갔습니다. 차감을 넣자 6.3장으로 안정됐지만 흑의 클리어율이 63% → 16%로
   떨어졌습니다 — **흑이 그 누수 위에 서 있었다는 뜻**이라, 패 파기 계수를
   1.5배로 올려 보상했습니다.
   손패 크기에 뚜껑을 씌우는 안도 재봤는데, **손패가 안 불어나던 문파까지
   함께 끌어내려**(백 58% → 39%) 정밀도가 떨어졌습니다. 차감이 정확한
   수단입니다 ([gdd/07 7-2](../gdd/07-turn-economy-revision.md)).
10. **한 문파에게만 시소 규칙이 꺼져 있었습니다.** 백은 어느 수치를 깎아도
   93%에서 안 움직였습니다 — 방어도 −30%도, 반탄 제거도, 임계점 조작
   제거도. 착지별로 재 보니 답이 나왔습니다: **합의 75%를 `적2`에 착지시키고
   거기서 평균 0.8 피해만 받고 있었습니다**(적은 `적3`에서 6.6). 마무리
   일격이 방어도에 통째로 먹혀 "작게 넘기면 큰 게 온다"가 백에게만 무효였던
   것입니다. **클로저 관통**([gdd/08 8-4-2](../gdd/08-boss-skill-loop.md))을
   넣자 93% → 42%가 됐고, 그 뒤로는 방어도 수치를 되돌려도 거의 안 움직입니다.
   백의 축은 방어도에서 **반탄**으로 옮겨갔습니다 — 지금 반탄을 지우면
   42% → 17%입니다.

### 남은 과제

- **흑이 67%로 크게 올랐습니다.** 파훼 규칙 변경의 최대 수혜자입니다 —
  되감기가 "합을 늘리는 유틸"에서 "파훼로 가는 경로"가 됐기 때문입니다.
  이제 흑은 약한 문파가 아니지만, 계획 상승폭이 여전히 낮아(−5%p) 잘
  써서 이기는 게 아니라 자동으로 이기는 쪽에 가깝습니다.
- **백/자의 파훼율이 1%대**입니다. 초식이 적게·무겁게 나가서 몰아치기가
  안 쌓입니다. 두 문파가 파훼를 안 써도 각자 이길 길(방어도·반탄 / 흡혈)이
  있으니 문제는 아니지만, 백의 빈틈 조작 카드는 정작 백이 못 쓰는 상태라
  **다른 문파에게 더 어울리는 효과**일 수 있습니다.
- **자 76%**가 가장 쉬운 문파입니다. 흡혈은 클로저 관통에도, 파훼 규칙
  변경에도 영향을 받지 않아 두 번의 큰 변경에서 모두 안 깎였습니다.
- 자동 AI는 방어·회복을 피해와 1:1로만 평가합니다. 실제 플레이어는 상황에
  맞게 쓸 수 있으니 위 수치는 하한선으로 보는 편이 맞습니다.

## 기획 문서에 없어서 임의로 정한 값

gdd에 규칙으로 적힌 수치는 위 표의 문서를 보시고, 아래는 데모를 굴리려고
이 구현에서만 정한 값들입니다 — 밸런스 튜닝 시 가장 먼저 검토할 대상입니다.

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 플레이어 최대 체력 | 80 | gdd 미기재 |
| 흘리기(evade) 적용 순서 | 부식·사혈 노출·방어도보다 먼저, 피해를 0으로 | 큰 일격일수록 이득이라는 성격을 살리기 위함 |
| 약화(Weaken) 배율 | 카드 피해 -25%, 다음 내 턴 한정 | gdd는 "약화 1턴"까지만 정의 |
| 취약(Vulnerable) 배율 | +50% (플레이어는 다음 피격 1회 소모) | gdd는 지속시간/배율 미기재 |
| 플레이어 방어도 | 매 플레이어 턴 시작 시 0으로 초기화 | 로그라이크 덱빌딩 장르 관례 |
| 보스 방어도 | 자연 감소 없음(플레이어 피해로만 소모) | gdd 미기재 |
| 보스 기술 피해량 | 적별로 상이 | 클로저 규칙 도입 후 시뮬레이션으로 재조정 — 수치는 `data.js`의 `ENEMIES`가 정본 |
| 흡혈 기준 피해 | 방어도 흡수 전 피해 기준 | 카드 설명("입힌 피해의 50%")과 일치시키기 위함 |
